# Claude independent review — firmware F1 (#46) + F2 (#47) vs main

## Correctness
### Blocking — none found.
### Significant
- SET_ANALOG_CAL performs an SD WRITE (`ainCalMirrorSd`) with no `CE_DISPLAY_ACTIVE` guard. Every other SD-write path in this firmware refuses unless the display is stopped; this is the first exception. Same-loop execution means no true race with `readFrame`, but it breaks the stated invariant and blocks the loop for `SD.remove` + `SD.open` + printf + close (ms) plus the 256-sample averaging (~10 ms at 40 µs/read) — visible frame hiccup if a trial is running. Recommend refusing sample/clear/deadband actions while `state_ != ALL_OFF` (consistent with 0x85/0xE0/0x8F), or at least documenting the exception.
- `return;` inside the SET_ANALOG_CAL inner switch (deadband length/range errors, unknown action) exits `handleBinaryCommand` entirely rather than `break`ing to the outer switch's end. If anything after the outer switch does per-command bookkeeping, these paths skip it — verify; other cases use `break`.
- 0xA4 reply grows 4 → 5 bytes. The Studio decoder tolerates it; any other host asserting exactly 4 bytes (older pyDisplayTools / MATLAB readers, other HIL suites) breaks. Worth a grep across sibling repos before merge.
### Minor
- `ainCalLoad` on an adc_bits mismatch invalidates the points in RAM but does not re-save, so EEPROM keeps the stale record until the next SET_ANALOG_CAL — harmless (re-evaluated every boot) but the SD mirror then disagrees with RAM until a save.
- `ainCalMirrorSd` returns false when SD is absent → `ain_cal_mirror_ok_ = false` reported as "SD mirror not written" — correct; but `SD.mkdir` result unchecked (fine, idempotent).
- Record CRC covers 20 of 22 bytes; magic+version+CRC validate — good. EEPROM.put write-back verify — good.
- `ainSampleRawAveraged` returns uint16 of a 32-bit accumulator average — fine for 12-bit.
- Mode 4 deadband uses ch1's record even though Mode 4 reads only AIN0 — correct by construction.
- Doc example fix (−20 = −200 fps/V) still pending in Modular-LED-Display.
## Tests
- HIL pytest only (no CI): shape tests for 0xA4/0xA5/0xA7, deadband round trip, bad-arg rejection, destructive open-point sample behind an env flag. Missing: a test that SET_ANALOG_CAL is refused (or not) while displaying — whichever behaviour is chosen should be pinned.
## Fit
- Constants/opcodes documented; capability bit 6; 0xA8/0xA9 reserved for the telemetry stream — consistent with the ring-buffer proposal.
## Adversarial
- Failure mode to think about: a board WITHOUT the LAB-209 rework saturates both points → `ainCalValidate` keeps the channel invalid (by design, good). A board with a marginal span (≥100 counts) passes validation with a wildly wrong slope — the Studio warns on a low +10 V point (<3000 counts); firmware could also require raw_open > ~2000. Reversibility: `clear` restores nominal scale; EEPROM record versioned.
